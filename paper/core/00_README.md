# 00｜作者编辑入口

**本目录是论文核心文档的唯一集中入口。编号用于定位，不是必须逐项完成的流程。**
你可以直接在 VS Code、Obsidian、其他 Markdown 编辑器或 GitHub 网页编辑这些文件。
AI 修改核心文档前必须展示具体路径、修改理由及最小 diff，并取得作者确认；已确认的同一差异不再重复询问。

## 我应该打开哪一份？

| 编号与文件 | 手动编辑什么 | 什么时候需要 | 不要在这里做什么 |
|---|---|---|---|
| [01_PROJECT_RULES.md](01_PROJECT_RULES.md) | 项目执行约定、可编辑范围、受保护资产、确认规则 | 首次对齐，或规则实质变化 | 不记录每日任务与实验成绩 |
| [02_RESEARCH.md](02_RESEARCH.md) | 科学问题、Research Gap、核心主张、作者方向决定、唯一正文入口 | 新材料改变科学判断 | 不把未验证想法写成事实 |
| [03_METHOD.md](03_METHOD.md) | 输入输出、数学对象、最小机制、竞争解释、可证伪预测 | 方法或理论论文；不适用时保持 draft | 不给综述强塞模型和消融 |
| [04_EXPERIMENTS.md](04_EXPERIMENTS.md) | 16 类 setting、split、信息访问、公平基线、loss、metric、预算 | 启动依赖这些定义的实验前 | 不复制训练参数，不要求跑完所有 setting |
| [05_REVIEW.md](05_REVIEW.md) | 综述类型、语料边界、检索与纳入、taxonomy、综合主张 | 综述；方法论文仅选用必要文献规则 | 不把 narrative survey 自动变成系统综述 |
| [06_LITERATURE.md](06_LITERATURE.md) | 原始论文的具体发现、局限、最近邻差异与原文位置 | 核验承担论证的文献时 | 不把摘要、搜索命中或下载数量当作深读 |
| [07_PROGRESS.md](07_PROGRESS.md) | 基于真实产物的进展、当前任务 gap、下一动作 | 一项工作改变判断或完成交付后 | 不复制批准字段，不把 CI 通过当作论文结论 |
| [08_EXECUTION.md](08_EXECUTION.md) | 实际代码/配置/数据入口、命令、输出位置、运行方式 | 准备执行、复现或交接时 | 不建立第二套 runner 或同名配置副本 |

论文正文仍在 `paper/draft/` 或作者确认的 TeX 入口；图源在 `paper/assets/`；
真实实验输出及既有记录仍在项目实际位置。这里只集中核心定义，不移动大数据、结果和正文。
`configs/*.yaml`、代码、BibTeX、日志和原始 PDF 保留真实用途需要的格式，**不把可执行配置改成 Markdown**。

## 最短使用路径

小论文：先核对 **02** 的问题与最近邻，再按当前缺口选 **03/04/08**；有结果后修改正文，不等待全部模板填满。
综述：先核对 **02** 的综述问题与近邻综述，再选 **05/06**；直接综合到正文，不套用训练流程。
纯理论：使用 **02/03** 明确命题、假设、证明与反例；数值实验不是自动前置要求。

## 人工编辑与 AI 编辑

作者手动修改是直接编辑，不需要 AI 再批准。模板存在、字段非空或校验通过不等于允许启动训练、付费调用或公开发布。
AI 处理核心文档时遵循：**读取当前文件 → 展示具体 diff 与影响 → 作者确认 → 重读避免覆盖并发修改 → 应用已确认差异 → 检查**。

| 情形 | 正确处理 |
|---|---|
| “帮我看看实验协议” | 只读分析；不修改核心文件 |
| “修改这里的 split” | 先提出具体新旧差异及影响，等待确认；不能自行选默认 split |
| “确认你刚才列出的 04/08 差异并写入” | 仅应用已确认差异，不再问相同问题 |
| 作者已经确认精确内容及范围 | 复用该次确认；文件内容冲突或科学范围改变才重新对齐 |
| 结果已产生，但进展页的新内容尚未确认 | 交付真实结果与拟议更新；不因等待写入 07 而阻塞独立的已授权工作 |
| 想先准备下一版 | 在对话中展示草稿；未确认不在 core 中写入“临时”“备份”或第二权威文件 |

确认可以一次覆盖一组明确文件和差异，不要求每个字符、每个实验队列项反复批准。
核心文档写入确认、实际任务授权与平台权限是三件不同的事；不能相互冒充。
此次模板改版本身不批准任何下游论文的方向、数据协议、预算或投稿。

## 02/03 的 Markdown 表格怎么填

普通说明和公式直接用 Markdown。需要程序检查的既有字段用 `Field / Value / Type` 表格：
只改 Value；text 是自然语言，json 用于 `true/false`、数值、`[]` 和少量结构化列表。
例如作者名列表写 `["作者姓名"]`，不能写 `yes` 代替布尔 `true`。不要改变字段键、复制同名字段或同时保留父字段空对象与子字段。
主张、贡献、实验、组件使用对应条目表，列表单元格如 `["C1"]`；不需要时留空表。

表格值中的竖线可写 `&#124;` 或 `\|`，换行用 `<br>`；长证明与推导写在表后并在字段中引用其标题。
示例放在 fenced code block 中，不会被解析为实际状态。相同字段不能在表中重复；额外说明不能暗中推翻正式字段。
校验器验证记录结构、正文来源和必要的科学引用，**不理解全部自然语言、验证人工身份或证明 claim 成立**。

## 从旧项目迁移

| 旧路径 | 本模板新路径 |
|---|---|
| 根 `AGENTS.md` 的规则正文 | `01_PROJECT_RULES.md`；根文件保留短入口 |
| `paper/paper.yaml` | `02_RESEARCH.md` |
| `paper/method/method_spec.yaml` | `03_METHOD.md` |
| `paper/refs/reading_matrix.md` | `06_LITERATURE.md` |
| `paper/STATUS.md` | `07_PROGRESS.md` |

本模板不保留可编辑的旧副本。已有下游项目可暂时继续读取旧格式；校验器不会自动迁移或回写。
迁移时先比对真实内容，确认后逐项转写并删除被替代的旧权威；新旧同类文件并存会报错，不会猜测哪一份有效。
不要把模板的 TODO 覆盖到已有科学内容上。可选 intake/idea-candidate YAML 仍是原有工具资产，不是新的日常编辑入口。

## 设计依据

- [OpenAI：AGENTS.md](https://developers.openai.com/codex/guides/agents-md/)：保留根目录的自动发现入口，集中规则用明确引用读取。
- [OpenAI：Skills](https://developers.openai.com/codex/skills/)：按任务加载，不把所有内容放进每次上下文。
- [NeurIPS Paper Checklist](https://nips.cc/public/guides/PaperChecklist)：实验划分、选择方式、资源和不确定性应可核验。
- [PRISMA](https://www.prisma-statement.org/)：适用于所声明的系统性综合，不强加给所有论文类型。

这些来源支持文档设计，不是 PaperTrace 已提高科研效率的实验结果。
