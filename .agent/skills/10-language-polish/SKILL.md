# 10 Language Polish

## Purpose

Improve expression without changing stable scientific content.

## Required Evidence

[Paper Skill Core](../../PAPER_SKILL_CORE.md), the original and adjacent text,
local terminology and the evidence/scope needed to disambiguate wording.

## Workflow

1. Identify the scientific content and strength that must remain unchanged.
2. Improve syntax, paragraph continuity and domain-native wording. Do not rename
   engineering structure into a scientific contribution.
3. For explicit anti-defensive revision, read `../anti-defensive-writing/SKILL.md`.
   Remove empty self-protection while preserving meaningful scope and uncertainty.
4. Move implementation details only when their new location preserves necessary
   meaning. Do not use a word blacklist.
5. Leave an unresolved scientific ambiguity explicit; route claim correction or
   substantive redrafting to the relevant Skill rather than polishing around it.

## Output

Revised prose directly. Disclose semantic removals only for explicitly requested
compression; provide changed pairs only when annotations are requested. Actual
reviewer responses belong to `13-reviewer-response`.

## Validation

Compare original and revised content once: claims, definitions, mechanisms,
examples, equations, values, citations, assumptions and limitations must survive.
For an explicit camera-ready task, check venue details and compile changed TeX.
No Python prose scoring, hedge inventory or repository-wide test for ordinary polish.
