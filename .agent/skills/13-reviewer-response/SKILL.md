# 13 Reviewer Response

## Purpose

Resolve actual reviewer concerns in the science and manuscript, then explain the
real revision in a point-by-point response.

## Required Evidence

[Paper Skill Core](../../PAPER_SKILL_CORE.md), the actual comments, authoritative
manuscript, relevant evidence and local author/venue decisions.

For a formatted response, use the bundled
[LaTeX response-letter template](assets/response-letter-latex-template/README.md).
Optional Markdown drafting starts at `paper/reviews/response_to_reviewers.md`.
These are reusable assets, not mandatory lifecycle records.

## Workflow

1. Identify each concern's root issue: novelty, theory, method, experiment,
   statistics, scope, expression or venue requirements.
   For requested `nature-response` assistance or a difficult response/package
   issue, read the relevant source through
   [task-specific selection](../../references/task_specific_skill_selection.md).
   Use it as one scoped support for actual editor/reviewer comments. A local reply
   does not require a known decision type; a package-level strategy uses the
   actual editor decision. Keep unavailable decision-dependent work explicit.
2. Choose evidence, correction, clarification, narrower claim or reasoned
   disagreement. Do not defend an unsupported claim through wording.
3. Perform the authorized scientific work or manuscript correction first.
4. Inspect outcomes and revise the claim when new evidence weakens it.
5. Respond with the answer, actual change, evidence, manuscript location and
   necessary boundary. Use comment IDs only where they aid coordination.
   Reuse the project's response text, author decisions and progress view; do not
   adopt a second tracker or readiness authority from the supporting Skill.
6. When LaTeX is requested, reuse an existing response working directory or copy
   the complete bundled template to a new `paper/reviews/response-letter/`.
   Never overwrite an existing response or put real comments in the reusable
   asset. Preserve reviewer text, style dependencies and relative inputs. Write
   directly in LaTeX when appropriate; a separate Markdown draft is optional.

## Output

Revised passages/files and professional responses grounded in performed work.
Clearly distinguish pending work from completed changes. A requested formatted
letter includes its editable source and, when compilation is available, PDF.
Keep one authoritative response text rather than synchronized Markdown/TeX copies.

## Validation

One final QA checks that every promised change exists, no experiment or source
check was fabricated and no implementation detail was promoted into novelty.
For a LaTeX letter, compile the working copy and inspect the rendered pages,
reviewer numbering and manuscript locations. Disclose an unavailable compiler;
do not call an uncompiled letter submission-ready. Keep template TODOs out of
actual submissions, not out of reusable assets.
Do not launch a second reviewer loop or mirror responses into multiple logs.
